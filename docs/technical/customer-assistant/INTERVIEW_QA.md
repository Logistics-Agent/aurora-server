# AI Customer & Operational Assistant — Interview Q&A Guide

> **Target Audience**: Junior, Mid-level, Senior & LLM System Design Interviewers  
> **Source-of-Truth**: Grounded 100% in NestJS `customer-assistant-service` implementation.

---

### Q1 (Junior): How does the Customer Assistant obtain live shipment data instead of hallucinating?
**Answer**:  
The assistant uses **Tool / Function Calling**. When a user asks about a tracking number or invoice, the LLM does not generate the data from its weights. Instead, it emits a structured tool call (`ShipmentLookupTool`), the NestJS backend executes a real gRPC call to `ShipmentWorkflow`, and returns the factual data back to the LLM to format into a helpful natural language response.

---

### Q2 (Mid): How do you prevent a prompt injection from accessing another tenant's shipment data?
**Answer**:  
Tool arguments generated by an LLM are never trusted with authorization identifiers. When `ShipmentLookupTool.execute()` is called, the tool retrieves `tenantId` and `customerId` directly from the authenticated session context (`ExecutionContext`), ignoring any tenant ID strings present in the user prompt or LLM arguments. The downstream gRPC service enforces multi-tenant query filters against the injected token context.

---

### Q3 (Mid): How does the service handle multi-turn conversation memory?
**Answer**:  
Multi-turn dialog state is stored in Redis under `chat:session:{sessionId}` as a sliding window of the last $K$ message turns with a 2-hour TTL. When a new query arrives, the orchestrator appends the active history to the prompt context. Summarization is triggered if total token count approaches the model's capability budget.

---

### Q4 (Senior): What happens when a downstream service (e.g. `BillingService`) is down during tool execution?
**Answer**:  
Each tool execution is bounded by a 4-second timeout and wrapped in a try-catch block. If `BillingService` fails with `503` or times out, the tool returns `{ success: false, error: "SERVICE_UNAVAILABLE" }`. The LLM receives this error and generates an apology response (e.g. `"I'm currently unable to retrieve invoice details due to a temporary maintenance issue. Please try again shortly."`) rather than crashing or throwing an unhandled HTTP 500 error.

---

### Q5 (System Design): Why decouple the Chat Orchestrator (NestJS) from the AI Gateway (Java)?
**Answer**:  
- **NestJS Orchestrator**: Optimized for asynchronous I/O, WebSocket connections, session management, and microservice tool aggregation.
- **Java AI Gateway (`ai-governance`)**: Centrally enforces token rate limits, prompt sanitization, model routing, and security policies across all platform services.
